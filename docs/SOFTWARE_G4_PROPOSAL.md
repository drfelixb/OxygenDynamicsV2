# Proposed G4 — durable, explainable BOI review results

27 September 2026 · **SW-G4-01 through SW-G4-04 approved under the stated fixtures and zero-run budget.** The exact two numerical replay targets and the C02 unavailable-amplitude example were [recorded before implementation](SOFTWARE_G4_REPLAY_TARGETS.md).

G3's demonstrated daily-use workflow is [accepted for usability](SOFTWARE_G3_USABILITY_ACCEPTANCE.md), with reliability and real-acquisition checks carried to G5. G4 addresses a different daily-use problem: a saved automatic result, a later researcher judgment and an exported number must remain distinguishable and understandable after MATLAB closes. Today `BOIRun.mat` reopens the automatic run, while boundary/reference revisions and some tissue decisions live in separate files. The [researcher workflow contract](RESEARCHER_WORKFLOW_AND_TRACEABILITY.md) requires a durable decision trail and calculation ingredients without making an unresolved scientific proposal into a result.

## Proposed bounded work

| ID / owner | User benefit and scope | Acceptance check and stop |
|---|---|---|
| SW-G4-01 · workflow engineer; researcher reviews decision wording | Link one existing automatic result to its separately saved review revision. Preserve event identity, boundary alternatives/preference, reference choices and source-specific tissue uncertainty where present, with actor/origin, reason, time, source/run IDs and prior/new values. Use existing review files and a small index/manifest only where needed; do not replace original files or invent missing judgments. | Close and reopen one existing researcher revision exactly. Use a **labelled synthetic decision fixture**, not a fabricated researcher judgment, to check that a changed choice saves as a new revision in a new folder. Automatic output and previous revision remain byte-identical. Stop if a reviewed item cannot be linked reliably—show it as unlinked, never attach by guess. |
| SW-G4-02 · workflow engineer; technical lead reviews persistence | Reopen automatic and reviewed views together, clearly labelled, without recomputation. Check compatible existing review files by identity/schema/hash; reject or label incompatible/missing stages. Provide a read-only compatibility path for the agreed older example, not a bulk migration. | Fresh MATLAB session reopens the automatic run and linked review; changing the new revision cannot change the original automatic tables. An incompatible small fixture gives an actionable explanation. Stop without rewriting historical review files. |
| SW-G4-03 · core engineer; validation engineer checks numerical replay | For **one saved event measure and one recording summary**, show the dictionary version, units, signal, support, time bounds, baseline if applicable, numerator/denominator, effective settings and unavailable reasons from saved ingredients. Keep automatic and reviewed quantities distinct; do not calculate a reviewed amplitude from an unapproved reference policy. | Independently replay those two selected numerical values from saved ingredients to the existing contract tolerance (exact where stored arithmetic permits). A missing ingredient is labelled unavailable, not reconstructed from raw data or treated as zero. Stop after these two examples, not an all-metric audit. |
| SW-G4-04 · workflow engineer; researcher judges readability | Export a concise human-readable result/review explanation and machine-readable provenance from the same dictionary and saved ingredients. Include stable source/run/revision IDs and relative links for files inside the export; identify external source references without exposing private absolute paths in the shareable view. | Export one event and one recording summary, compare readable and structured values/IDs, then move **a copy** of the new export folder and reopen supported internal links. If an external source cannot move with it, state that dependency plainly. Stop at a readable example, not a report redesign. |

**Fixtures and budget:** use the completed G2 ID400 `gui-run` for a saved-run recording summary and the existing `reference-validation/boi-researcher-reference-display-20260915/final/export-row-186/` packet with its indexed C02 audit for a reviewed event. These are **different source identities** and will be assessed separately, never merged. One labelled synthetic decision/incompatible-file fixture exercises revision and rejection behavior. First verify exact source/result/review associations read-only. Use only new revision/export folders, with no new detector, statistics, recorded full-movie or cohort execution. Run focused persistence/export/numerical-replay checks and one bounded local BOI regression gate after code changes; no repeated G3 journey or dataset campaign. If a required saved ingredient is absent, report the G4 limit and propose a separate capture change rather than rerunning a recording by default.

**Scientific and output boundary:** expected changes are review linking/persistence, presentation, new export files and tests. Existing source recordings, automatic results, accepted correction/detector/measurement rules, prior review files and scientific uncertainty remain untouched. A changed judgment creates a new explainable revision, not a replacement result. Formula, baseline, tissue-support or other scientific-output changes require a separate impact review and researcher approval. No KX/stimulation/protocol work, new estimator, platform rewrite, release publication or G5 failure campaign is included.

**Milestone gate:** the researcher can close–reopen the selected existing review exactly, distinguish automatic from reviewed evidence, trace one event and one recording summary to their saved ingredients, and read the resulting export after a supported folder move. A synthetic changed choice demonstrates non-destructive revision saving without attributing a new scientific judgment to the researcher. Record any unavailable ingredients and unsupported legacy cases. Stop at these examples; no exhaustive labeling. If deferred, G3 remains usable, but decisions stay scattered across separate files and a collaborator must assemble the calculation/provenance chain manually. This approval does not approve G5 tests or a release.
