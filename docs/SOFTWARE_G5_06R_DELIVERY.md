## Implemented

The new [isolation guard](../../reference-validation/software-g5-isolation-revision-20260928/isolation_guard.py) is launch-agnostic and has no MATLAB/Run entry point. It uses macOS `proc_pidinfo` to identify a process by PID, microsecond birth time and UID, cross-checks `ps` parent/group/UID fields, records session and command, and retains observed descendants after reparenting. Its sample log records actual intervals; a trigger writes the prior and current full process tables, first-seen process records, group/parent transitions and explicit ancestor chains **before** signalling. A reported worker PID can be separately attested against a live command and precise identity before any future release decision. The diagnostic evidence cap is 32 MiB with a reserved trigger/report allowance.

The stop path verifies original-group membership before signalling that group, signals verified escaped PIDs separately, and falls back to verified individual PIDs if group membership is unsafe. It tracks new children during cleanup, escalates verified survivors, records each signal target and requires two clean observations at least one second apart. An unverified identity, monitor/evidence failure or survivor is a containment failure. `ps` sampling cannot guarantee detection of a process that detaches and disappears between samples; this limitation remains explicit. The [synthetic fixture and runner](../../reference-validation/software-g5-isolation-revision-20260928/run_synthetic_check.py) have no recording or MATLAB path. The old one-use SW-G5-06 packet and its accepted stop report remain unchanged.

## Self-review correction after the third check

The saved reparenting trace shows a brief interval where `ps` still listed the exiting parent while `proc_pidinfo` no longer returned it, followed by a zombie row. The initial code treated that single exit transition as PID reuse. The revised guard now keeps such a PID *potentially live* for that sample, reports an identity problem only if it remains unidentifiable across snapshots, and still fails closed for a definite microsecond-birth mismatch. It also immediately signals verified individual group members if a group-wide signal cannot be safely made, records explicit ancestor chains, and adds reported-worker attestation. **Seven** saved-table/unit checks pass, including a regression for the observed exit pattern and the group fallback. These changes were made **after** the live synthetic reparenting check, so they do not supply a passing live reparenting result.
