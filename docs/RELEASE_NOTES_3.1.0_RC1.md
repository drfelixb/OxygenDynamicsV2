# OxygenDynamicsV2 3.1.0 RC1

This MATLAB release candidate focuses on the bioluminescence oxygen imaging workflow, from a recording list through saved analysis and Excel export. The Batch Editor gives each recording a visible status and keeps completed results available for the next session.

## Changes since the previous GitHub release

The previous release, **OxygenDynamicsV3 `v3.0`**, was published on 4 June 2026 at commit `329cdc2`. It already provided a stepwise GUI, recording preflight, raw and denoised TIFF handling, sink and surge analysis, event-based hypoxic burden, detailed statistics workbooks, and regression checks. [Previous GitHub release](https://github.com/drfelixb/OxygenDynamicsV2/releases/tag/v3.0) · [Tagged workflow and output descriptions](https://github.com/drfelixb/OxygenDynamicsV2/blob/v3.0/README.md)

### Batch setup and execution

- The **Batch recordings** editor accepts recording folders and existing CSVs. Relative paths resolve against the CSV folder. If an absolute path uses another computer's folder layout, **Choose local folder…** maps a shared original root to its local counterpart. **CSV setup** can apply sampling rate and pixel size only to rows that are missing those values.
- An imported CSV opens as a protected source. **Save as…** creates a separate working CSV for edits, run links and history. The recording table stays visible across the workflow tabs. **Check rows** identifies blocked inputs and distinguishes verified saved results from files that are incomplete, missing or associated with different settings.
- Blank batch support settings use the **Automatic tissue estimate**. A matching saved craniotomy ROI can be selected explicitly. The choice and its source are retained with the run. The estimated tissue boundary needs visual inspection, and the automatic mode can admit detections beyond that boundary.
- The Run tab previews selected, runnable, skipped and excluded rows and offers expandable details. It executes eligible recordings sequentially. **Stop after current recording** completes the active recording before stopping the queue. Reopening the working CSV and checking the rows makes previously verified work available to skip. An explicit retry creates a new attempt folder.

### Saved results, review and exports

- A completed run can be opened from its working CSV row or from its indexed `BOIRun.mat` folder. The saved-result workflow exposes event traces and recorded image support. A reviewed pocket can save explicit event and reference frames, recovery and reference qualifications, and separate raw and corrected optical measurements in a new revision. That revision can be reopened and exported from its saved evidence.
- **Automatic export** collects selected completed saved recordings into the detailed workbook, MAT tables and companion files. The preview lists included and excluded recordings and the destination. Export progress identifies loading, writing and verification. The finished export remains available from **Open existing export…** by selecting the completed `BOIBatchStats_…` folder. Reopening requires only the saved combined output and receipts.
- **Reviewed export** is an optional burden-only companion built from explicitly selected compatible saved review artifacts. A saved recognition decision can exclude a detection. A matching approved event result can supply reviewed timing, area or amplitude. The companion records what came from a review, what remained automatic and which required values were unavailable.
- **Compact workbook** projects saved values into **Events**, **Recordings**, **Sites**, **TimeSeries**, **Availability** and **Definitions**, with **Phases** when supplied. Source, destination, Preview and Export are visible together. Compatible reviewed outputs, metadata and phase annotations are optional. The exporter retains saved policy and missingness, and the Availability sheet gives grouped counts and exact source-row locators. When the matching automatic MAT burden data exceed the small-table limit, the receipt-validated automatic workbook can supply the six corresponding saved tables. The exporter assembles and checks the `.xlsx` locally before copying the completed workbook and checksum receipt to the selected destination.

### Measurements and interpretation

- Event measurements distinguish saved native event geometry from site-level summaries. The event amplitude is sampled on a fixed event footprint from preserved input. The event's mean native area, timing, optical reference, sign convention and measurement availability have distinct fields. Recording and window summaries expose support and exposure ingredients for each event sign, including calibration and timing assumptions.
- New BOI statistics have an explicit versioned local sink reference with quality flags, including short, overlap or recording-start cases. They retain the original strict optical amplitude and separate pre-episode measurement. The earlier-recording reference contributes a separate comparison flag, with unavailable values where the comparison cannot be assessed.
- The tagged `v3.0` burden code could infer amplitude direction from a median, fall back to a site area and sum available contributions while omitting missing ones. The candidate records the actual reference and sign policy, uses event-specific area and distinguishes a complete total from unavailable evidence. Finite signed contributions now include negatives, which subtract from a complete total. An unavailable required ingredient withholds the complete burden. A verified analyzed recording with no events is distinct from an incomplete recording.
- The event composite still multiplies the selected amplitude in percent by event area in µm² and duration in seconds. The area- and time-normalized recording total multiplies the complete event sum by `1e6 / analyzed area in µm²` and `60 / recording duration in seconds`. Compare results only after confirming event membership, the reference and sign policy, area and time denominators, and missingness. ## Comparison with the original paper-published code

The original baseline is **Temp2Spec/OxygenDynamics_Public: Science_2024**, archived on 7 February 2024 at commit `a3f4bee5d08f5f6000448a9be7b0059b9a4a6866`. It accompanied the paper *Oxygen imaging of hypoxic pockets in the mouse cerebral cortex*. [Original software archive, DOI 10.5281/zenodo.10629901](https://doi.org/10.5281/zenodo.10629901) · [Science article, DOI 10.1126/science.adn1011](https://doi.org/10.1126/science.adn1011)

| Area | Science_2024 | 3.1.0 RC1 |
| --- | --- | --- |
| Workflow | A CSV-driven MATLAB wrapper ran imaging and optional behavioural processing. A separate curation app accepted or rejected candidate sinks, and the statistics script collated output. | The Batch Editor adds portable paths, explicit input checks, working copies, recorded attempts, verified skip and reopen points, alongside the preserved script entry points. |
| Detection and intensity inputs | The wrapper consumed motion-corrected imaging input, which could already be denoised. The original sink amplitude used a processed, convolved site trace and a fitted seventh-order polynomial trend. | Optional denoised data can feed detection while preserved input feeds optical quantification. `DetectionOxySinkAmp` identifies the processed-trace diagnostic. Current `NormOxySinkAmp` and explicit percent fields describe preserved-input optical change relative to their recorded event reference. The historical and current `NormOxySinkAmp` identifiers describe different measurements. |
| Human review | The curation app produced a separate curated candidate table after yes/no decisions. | Saved review artifacts add interval and reference decisions, original and corrected trace context, source and calculation evidence, and revision-aware export. Automatic and reviewed values remain separately identifiable. |
| Tables and reporting | The original scripts already produced summary CSVs and included a standalone event-metrics spreadsheet script. | Detailed exports are complemented by a compact identity-keyed workbook, saved policy and availability, completion receipts, and distinct automatic and reviewed datasets. |

The updated outputs describe relative optical intensity on recorded acquisition and analysis supports. Oxygen concentration, physiological recovery, comparative detector performance and agreement across acquisition conditions require separate validation. Researchers reproducing published calculations should keep the historical code archive and outputs identified by their original version. [Original software archive](https://doi.org/10.5281/zenodo.10629901)

## Migration and resumable work

[One-page MATLAB guide](BOI_BATCH_QUICK_START.pdf)

1. Extract the new version into its own folder and follow the MATLAB path setup. Keep the prior installation available for historical analyses. [Installation](../INSTALLATION.md)
2. Open your recording CSV, map local folders where needed, and save a working copy. To resume queue work, reopen the working CSV, run **Check rows**, and review the remaining recordings. The original CSV and already completed run folders remain usable as source records. [Batch Editor guide](BOI_BATCH_EDITOR.md) · [Queue execution and recovery](BOI_BATCH_EXECUTION.md)
3. To continue from a completed recording, open its existing run via the selected row or its completed `BOIRun.mat`. To start from an existing combined export, select its entire completed folder with **Automatic export → Open existing export…**. Leave its saved files together and choose it as the source for the optional reviewed or compact export. Earlier outputs can still be used in their original readers when they lack the newer indexed receipts.
4. To compare old and new outputs, preserve the source versions and choose the same observation unit. Re-exporting saved values to the compact format preserves the original saved policy. Running new statistics can produce different values under the current definitions and writes a separate combined export.
