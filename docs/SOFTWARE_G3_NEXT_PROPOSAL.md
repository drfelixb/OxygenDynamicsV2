# Proposed next G3 slice — prepare and run one BOI recording clearly

27 September 2026 · **SW-G3-04 through SW-G3-06 approved as a bounded partial G3 slice.** The researcher authorized at most one small synthetic end-to-end execution and zero recorded full-movie runs. Stage progress must be visible in the GUI during that execution. Workbook launch and native chooser usability remain open; this slice cannot close all of G3.

The approved [saved-result slice](SOFTWARE_G3_PARTIAL.md) can reopen and inspect the G2 ID400 run. The researcher confirmed the revised event-row behavior on 27 September. The remaining G3 gap is the path **before and during a new run**: the current window has validated fields and a preflight, but its long text mixes known input facts with warnings, and progress is reported mainly in the MATLAB Command Window. This proposal would make that path understandable without changing BOI calculations.

**Expected effect:** MATLAB UI presentation, preflight/run status handling and focused tests change. The accepted correction, detector, timing and measurement rules, source-specific tissue support, automatic/reviewed separation, missingness, saved scientific table definitions and previous G2/G3 outputs stay fixed. Existing `BOIRun.mat` and `RunStatus.json` contracts remain the source of truth. This proposal does not authorize KX, stimulation/protocol work, cohort analysis, a new estimator, a platform rewrite or release publication.

**Effort and test limit:** two incremental implementation items plus one bounded walkthrough, small deterministic fixtures first, at most one synthetic full-pipeline execution, zero recorded full-movie executions, then the relevant local BOI regression gate. Keep the before-state and write new outputs only to a new local packet. If a change would alter scientific output or require a recorded-movie run, stop and seek a separate decision with its numerical impact.

**Alternative:** defer this slice. The accepted saved-result route and existing preflight remain available; the fresh-run journey continues to require the current technical text and Command Window progress. The [software plan](SOFTWARE_DEVELOPMENT_PLAN.md) keeps full G3.2/G3.3 and fresh-run acceptance open until a separately approved slice is demonstrated. Human testing of native chooser and workbook launch from the saved-result slice is still unclaimed.
