## Problem and first slice

A synthetic success showed the GUI's staging → analysis → statistics → complete progress, and one staging source failure showed a clear message and an excluded incomplete folder. It remains untested whether a failure **after entering analysis or statistics** leaves an honest saved status and offers a safe next action. The first G5 slice checks precisely those lifecycle paths without running a recorded full movie or changing scientific rules.

**Execution budget:** at most **two disposable synthetic failure attempts total**, with at most **one small synthetic detector execution** (only if needed to reach statistics), **zero recorded full-movie executions**, and **zero cohort runs**. Use only new output folders and the existing G3-sized synthetic fixture design; never inject failure into, alter or overwrite the G2/G4 saved results or original sources. One focused contract/failure test group and one local BOI regression gate after code changes are allowed. Do not repeat the full G3 journey. If the chosen stage or resource bound cannot be guaranteed, stop before that Run and report it untested. Preserve every generated failure folder for review.

**Affected outputs and scientific meaning:** expected changes are test harness/fixtures, failure/status/recovery presentation if a reproducible defect is found, and a G5 evidence record. Accepted BOI correction, detector, baseline, tissue, event and statistics definitions and existing result values stay unchanged. A reproducible scientific-output defect may be documented with a candidate fix, but adoption needs separate numerical-impact review and approval. No KX/stimulation/protocol work or new biological claim is included.

**Gate after this slice:** show the two GUI failures beside their `RunStatus.json` files, incomplete-folder rejection and new-directory recovery path. Clearly mark any unexercised stage or engine-internal behavior. Passing SW-G5-01–03 would close only this synthetic failure/recovery slice, **not G5 or release**. If deferred, the accepted G3/G4 usability work remains available, but analysis/statistics failure handling and incomplete-run recovery remain unverified.

The remaining G5 work needs its own fixture list and budget before execution: a **named real acquisition** fresh-run check; invalid/corrupt/incompatible/zero-event/missing-baseline and both-sign cases; runtime and peak memory on approved fixtures; supported MATLAB/toolbox/OS matrix and hosted CI; no-overwrite/version/dependency/licensing/private-path checks. These may use saved results or small fixtures where they genuinely cover the contract. Any recorded full-movie run requires a separate explicit proposal with source identity, expected time/storage, output location and maximum executions. Unchecked platforms and failure classes will be labelled untested. No release approval is requested here.
